# P0 agent evaluation — ai-pipe

Date: 2026-08-07

## Decision

Proceed to RI-1 response-budget completion and the SC-1 elided-source
experiment. Do not enable structural expansion by default.

The assisted comparison found no accuracy difference: both profiles answered
all eight tasks with exact gold file and symbol sets. Structural retrieval used
fewer calls and slightly less agent work on average, but returned substantially
larger tool payloads. With one run per task and no accuracy headroom, this is a
useful direction signal, not evidence that structural expansion improves task
success.

MCP availability alone also did not produce adoption. The product needs an
explicit agent integration contract or installable guidance; server metadata
is not sufficient in the tested Codex client.

## Corpus and protocol

- Repository: `ai-pipe`
- Frozen commit: `ea13166c59cfc52574e96959413f5c54be20e8c8`
- Tracked files: 930
- Indexed JS/TS files: 690
- Chunks: 5,483
- References: 28,527
- jscout snapshot:
  `89d816adb5089f167441ddd26a68b43159b322e7d587285f433f1db204c17885`
- Agent: Codex CLI `0.147.0-alpha.6.5`, `gpt-5.6-terra`, low reasoning
- Tasks: eight fixed lookup, one-hop, blast-radius, multi-hop, workflow, and
  uncertainty questions
- Trials: one run per task/profile; profile order counterbalanced by task
- Grading: exact set equality for claimed production files and symbols
- Isolation: read-only frozen checkout, isolated Codex configuration, no web,
  browser, apps, plugins, or other MCP servers

The assisted prompt required both profiles to start with jscout and use it as
the primary localization interface. It did not require the structural profile
to use expansion or `neighborhood`.

Across all eight tasks, baseline made 39 jscout calls and structural made 25.
Structural selected expanded semantic search in seven tasks. It never selected
the standalone `neighborhood` tool. There were no MCP or runner failures.

The aggregate structural reduction is not uniform. For example,
`pattern-journal-callers` used 72,810 more agent tokens under structural, while
`runtime-secret-consumers` used 71,819 fewer. Repeated trials are required
before treating the mean deltas as stable.

## Adoption result

An unassisted 16-run pass made zero jscout calls across both profiles. After
adding profile-aware MCP initialize instructions, a natural-prompt lookup check
still made zero calls and chose shell search. When the prompt stated the agent
integration contract, the workflow check used expanded search and exact
definition drill-down without being told which structural tool to select.

This separates two product questions:

1. Does an agent use an available repository index by default? Not in this
   client/configuration.
2. Once integrated, does structural context improve behavior? It matched
   correctness with fewer calls and less average work, but its output was too
   large and the sample was too small to claim a task-success improvement.

## Architectural consequences

- Keep expansion opt-in. Simple lookups showed no accuracy need for it.
- Finish whole-response byte/token budgets before expanding graph scope. A
  single structural search returned more than 40 KB in multiple trials.
- Make SC-1 compare full versus elided source at equal rendered budgets. The
  current result identifies payload size—not graph latency—as the immediate
  constraint.
- Treat `neighborhood` as unproven product surface. It passed fixture and
  latency checks but had zero natural selection in this task set.
- Ship agent integration guidance with the MCP setup. Server instructions stay
  as protocol-correct metadata, but cannot be the only adoption mechanism.
- Repeat the paired suite with multiple seeds and add edit/plan outcomes before
  changing the default retrieval policy.

## Limitations

- One stochastic run per task/profile; no confidence interval.
- All tasks were answerable by both profiles, leaving no accuracy headroom.
- The grader treats file and symbol outputs as sets, so it does not validate
  path ordering in the macro trace.
- `ai-pipe` contains extensive repository-local skills and documentation that
  can alter localization behavior.
- Token totals include all agent context and tool payloads, not only source
  evidence selected by jscout.
- The suite evaluates repository localization and explanation, not code edits
  or regression avoidance.
